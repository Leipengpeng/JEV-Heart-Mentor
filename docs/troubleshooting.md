# 排障

优先用合成演示判断是界面、模型还是微信数据接入的问题。排障不需要分享真实聊天、密钥或会话 token。

| 现象 | 检查方式 |
| --- | --- |
| `chatlens` 命令不存在 | 激活安装时的虚拟环境，再执行 `pip install -e .`；也可用 `python -m chatlens demo --open` |
| 演示未打开浏览器 | 终端会显示 `127.0.0.1` 地址，在同一台电脑打开；不要把地址当成公网服务 |
| 演示分数始终一样 | 合成演示使用预置结果，不运行模型；真实模型流程见设置指南 |
| `xcrun` 或 Swift 编译器不可用 | 安装 Xcode Command Line Tools；当前原生构建目标是 Apple Silicon / macOS 14+ |
| 提示缺少模型依赖 | 在当前虚拟环境执行 `pip install -e '.[models]'`，然后运行 `chatlens doctor` |
| 提示权重不存在或加载失败 | 核对 `CHATLENS_MODELS_DIR`，执行 `chatlens download-models`；不要仅用目录存在判断下载完成 |
| 第一次分析较慢 | 等待两套模型加载。后续仍慢时检查内存压力、输入长度和其他占用 GPU 的程序；没有固定延迟保证 |
| 只有“是否分析”或空白卡片 | 新联系人需要明确点击“分析”；“暂不”不会启动该联系人的模型分析 |
| 历史列表为空 | 先执行 `chatlens import-json examples/conversation.json` 验证导入；微信数据库不会自动变成可读数据 |
| 提示未配置数据适配器或密钥不匹配 | 使用 JSON 导入，或按设置指南配置外部模块、源目录和已有有效密钥；应用不自动登录或获取新密钥 |
| 点击微信消息没有反应 | 核对系统辅助功能权限、聊天窗口可见性与联系人识别。若 OCR 回退需要权限，再由用户在系统设置中开启屏幕录制 |
| 相同文字匹配出多条消息 | 从候选或本地历史点击准确消息，不要用最近一条替代目标句 |
| 点击自己的消息没有建议 | 分析对象限定为对方；自己的发言仅作为上下文 |
| 切换联系人后暂时等待 | 前一轮推理可能仍占用唯一工作槽。程序会防止旧结果覆盖新选择，等待释放后再分析 |
| 有分数但文案未完成 | JEV 评分已完成，MiniCPM 表达或校验失败。系统最多尝试一次具体错误修正；失败时保留评分 |
| 报上下文超过预算 | 当前 JEV 上限 1024、MiniCPM 输入 3000 tokens；特别长的单条锚点可能无法完整放入，不会自动把它当作普通短句 |
| Windows / Linux 无法运行真实模型或原生窗口 | 当前仅支持演示、JSON 导入和纯 Python 规则；完整路径依赖 macOS MLX 与原生 API |

## 安全地重启

在原来的虚拟环境与配置下运行：

```sh
chatlens launch --restart --main
```

启动器只处理有自身记录且进程命令匹配的进程。不要为了重启而删除历史数据库、密钥或整份 `DATA_DIR`。若服务启动失败，可在本机运行 `chatlens serve` 查看错误；它的启动输出可能含会话凭据，不要原样发布。

## 提交可复现的问题

提供操作系统、CPU 架构、Python 版本、步骤与错误类型即可。对模型或上下文问题，请把场景改写成全新的虚构对话，保留触发问题的结构。截图只使用 `chatlens demo` 或合成导入数据。

不要上传 `DATA_DIR`、微信导出、数据库、解密快照、密钥、会话文件、真实截图或包含原文的调试记录。模型权重也不作为附件提交。参见 [贡献指南](../CONTRIBUTING.md) 与 [隐私说明](privacy.md)。
